# SEO/GEO/AEO bot — playbook

Updated each run. Read this AND CHANGELOG.md at run start.

## Current understanding (2026-08-25, run 5)

- Site: 116 pages, Astro static, push to main = deploy (Cloudflare Pages). Deploys land in **under 2 minutes**.
- **GSC 90d baseline (2026-05-25 → 2026-08-22): 42 clicks / 9,500 impressions / 0.44% CTR.** Use 90d windows. 819 query×page rows total, so the full dataset is small enough to pull whole.
- **The constraint is authority.** Unchanged from run 2 and reconfirmed twice since: the technical foundation is good, and the commercial head terms sit at position 40–72 because nothing points at this site. Bing still reports **zero tracked inbound links** (re-checked 2026-08-25). 🟡 Bing's link data is unreliable; confirm in the UI before treating as fact.
- **Where this site ranks, it ranks for questions, not keywords.** This is the run-4 and run-5 thesis merged, and it is the single most useful idea in this file. Two independent confirmations:
  - `/services/90-day-growth-sprint` holds **position 1.0–5.6** on provider-selection prompts ("who offers / top providers of / which agencies provide / get a quote for"). Eight of the ten site-wide non-brand queries at position ≤5 land there.
  - `/insights/when-to-hire-fractional-cmo` holds **position 8.0–8.3** on three-way hiring-decision prompts ("should a series a startup hire a fractional cmo a growth agency or wait to hire a full-time vp of growth", 38 imp across two variants). The same decision shape recurs across the whole cluster at every position from 8.5 to 94.3.
  - Meanwhile `/services/fractional-cmo` sits at **position 51.8 across 1,624 impressions** of head terms (`b2b fractional cmo` 244 imp @ 51.7, `saas fractional cmo` 215 @ 43.8). Head terms are authority-bound. Question-shaped queries are not.
  - **Working rule:** find the queries phrased as questions or decisions, check which page Google already chose for them, and make that page answer the question in one extractable passage. Do not fight for the head term.
- **The rule "don't optimise titles/meta at position 45+" holds — and implies its inverse.** At position 1–10 the snippet and the first extractable passage are the whole lever. Runs 4 and 5 both acted on that.
- **Profile-page impressions are brand sitelink artefacts. Do not chase them.** `/proof` (334 imp), `/press` (313), `/facts/we-scale-startups` (192), `/about/daniel` (179), `/start-here` (96), `/podcast` (78), `/speaking` (54) are almost entirely the single query `we scale startups` at **position 1.0 with zero clicks**. Google logs one impression per sitelink URL at the parent result's position, and the homepage absorbs the clicks. The tell is the same query at the same position 1.0 across many pages. Check the query mix before believing a page-level position.
- **A second chunk of homepage impressions is brand-name collision**, not demand: `we scale`, `start and scale`, `wescale`, `we scale ab` (a Swedish company), `calconnect login`, `google for startups in shoreditch` (39 imp at pos 3.1 — someone looking for Google's campus, not WSS). ~800+ impressions of people looking for someone else. Discount them from every CTR calculation.
- **The site has AI visibility it does not have classic search visibility.** Hundreds of impressions of long, conversational, personally-phrased prompts, all zero-click. Optimise for passage extraction — a direct-answer paragraph under a heading, named facts, prices, durations, comparison tables — not for titles the user may never see.
- Entity graph is rooted on danieljohnson.xyz for Person, wescalestartups.com for Organization. `/facts/*` pages carry `lastUpdated` — keep them monthly-fresh.
- The repo emits six `ai:*` meta tags on all pages, five hardcoded and identical sitewide. No crawler consumes those names. Harmless, inert, **do not expand**. Note `meta-ai:summary` is derived from the page description, so improving a description improves it for free.
- `site.ts` is the single source of truth for pricing/proof/FAQ copy; page copy MUST match `pricingTiers`. The **numeric** ranges for structured data live in `src/lastmod.ts` (`servicePriceRanges`). `/insights/fractional-cmo-cost-uk` is the canonical place for the agency (£6k–£20k/mo) and full-time (£120k–£180k base) comparison bands — reuse those, do not invent new ones.
- **robots.txt says `ai-train=no` as of 2026-08-25.** Run 2 changed this to `yes`; Daniel reverted it with an explicit comment. That is his call and it is now coherent — GPTBot/ClaudeBot are still `Allow`ed for retrieval. **Do not re-flip it.**
- Daniel works in the repo directly, and so does this bot several times a day. Check `list_commits` before choosing a file; do not touch a template another run edited hours ago.

## Connector and environment notes

- **The sandbox can clone, install and build the repo.** This corrects run 4's playbook, which said only Daniel's local clone could. `git clone` + `npm ci` (~22s) + `npm run build` (116 pages, ~3s after OG generation) all work, and the GitHub connector pushes. **Verify every change this way before committing** — run 5 confirmed build, `astro check`, JSON-LD parsing, rendered HTML and internal-link targets before the commit existed.
  - Trap 1: `git clone` writes ~10,000 lines of output and will blow the tool's token limit. Redirect everything to a log file and `tail -c` it.
  - Trap 2: **a shallow clone breaks `refresh:lastmod`** — with `--depth 1` every file resolves to the clone date and the script rewrites all 78 routes. Use `git fetch --unshallow` first. (Same reason CI needs `fetch-depth: 0`.)
  - Trap 3: cloned files are read-only to `rm -rf`; use a fresh directory name rather than deleting.
- **`/insights/*` routes are NOT in `staticPathLastModified`.** They fall back to `siteConfig.siteLastModified`, so **the sitemap two-step does not apply to insights content changes** — `check:lastmod` will be green with zero routes updated. The two-step still applies to static pages and service/case content.
- **GSC MCP `row_limit` is yours to set and the default (100) silently truncates.** Rows come back clicks-desc first, then **zero-click rows sorted alphabetically by (page, query)** — a low limit guillotines everything after roughly `/f…`. Always pass `row_limit: 25000`. `dimensions: "page,query"` at that limit returns the whole 819-row dataset in one call.
- Large GSC pulls exceed the tool output limit. Run them in a **subagent** with an explicit list of the figures you want back, so the dump stays out of main context.
- 60–89% of a page's impressions can be **anonymised** by Google (rare, personally-phrased queries). Named-query impressions will not reconcile to page-level totals. That gap is itself a signal: it skews heavily conversational.
- GSC MCP is read/inspect only — no request-indexing endpoint. Recrawl comes via the sitemap.
- Bing MCP tools need the `self="bing"` arg quirk. Quota ~97/day, ~697/month remaining. **Bing query/page/rank-stats endpoints are broken** (schema validation error on returned dates); crawl issues, quota, link counts and URL submission work. `submit_url` returns `null` on success.
- **Bing crawl-issue data is historical, not current.** It still lists URLs fixed weeks ago. Always re-check live before acting on it.
- Cloudflare MCP has no Pages-deployment tools; verify deploys by fetching the live URL with a cache-busting query string.
- **`mcp__workspace__bash` curl works fine against the site** for status codes and redirect chains, despite the SKILL note about bot challenges. `web_fetch` sometimes returns a stale cached body — **trust curl status codes over web_fetch bodies when checking redirects.**

## Standing decisions

- **Every commit boundary must be a state that builds.** If a change spans files, push the files together.
- **Verify the build against the tree you pushed, not the tree you have locally.** Since run 5, do this in the sandbox: clone, `npm ci`, apply the change, `npm run build` + `astro check`, and inspect the rendered `dist` HTML — *before* the commit exists.
- **Sitemap lastmod is generated, not hand-edited.** Two-step on static/service/case content: commit the content, then `npm run refresh:lastmod` and commit the result. Does not apply to `/insights/*` (see connector notes).
- Prefer content-only commits; avoid layout/CSS the bot can't visually verify. Reusing an existing component on an existing code path is fine; adding a page to a template's special-case list is not worth it if the same text already renders elsewhere in the DOM.
- Always fetch the live URL post-deploy before declaring success, and re-test that new redirect rules did not shadow existing specific ones.
- Never state market statistics that aren't sourced; anchor cost claims on WSS's own published ranges, and reuse the bands already published on `/insights/fractional-cmo-cost-uk` rather than minting new ones.
- **Keep the "point them somewhere better" voice.** Every comparison the site publishes should name the case where a competitor or a different model is the right buy. It is the brand voice and it is also what makes a passage worth citing.
- **When a change is defensible under two competing readings of the data, prefer it** over one that requires the ambiguity to be resolved first.
- Mark confidence explicitly (🟢 verified / 🟡 inferred / 🔴 vendor-sourced). Most GEO research is published by companies selling GEO tools.
