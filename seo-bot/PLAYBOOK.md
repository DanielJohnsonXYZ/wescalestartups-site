## Connector and environment notes

- **The sandbox can clone, install and build the repo.** `git clone` + `npm ci` (~22s) + `npm run build` (~3s) all work; the GitHub connector pushes. **Verify every change this way before committing** — build, `astro check`, JSON-LD parsing, rendered HTML, internal-link targets, sitemap arithmetic, all before the commit exists.
  - **Traps 1–8 are stated in full in the task file's FIXED RULES. Do not restate them here.** The three that have cost real time: **Trap 2** — a shallow clone makes `refresh:lastmod` rewrite all routes; `git fetch --unshallow` first. **Trap 5** — `check:lastmod` cannot fail before the content commit exists; a green pre-push result means nothing. **Trap 8** — never revert on an empty `web_fetch`.
- **`staticPathLastModified` covers 83 routes including SOME `/insights/*`** — the four pillars, `/insights` and `/insights/glossary`; every other insight falls back to `siteConfig.siteLastModified`. **So the sitemap two-step DOES apply to the pillars**, to static pages, and to service/case content. Runs 5–8 recorded the opposite and run 9 left CI red trusting it. **Do not guess: `grep` the route in `src/lastmod.ts`.** **The script only refreshes routes already in the map — it never adds one**; insert a placeholder key and let `refresh:lastmod` write the real date.
- **GSC MCP `analytics_query` SILENTLY ANSWERS ABOUT THE WRONG PROPERTY IF `siteUrl` IS OMITTED. It does not error.** The account holds 31 sites including a stale `https://www.wescalestartups.com/` URL-prefix property left from the pre-May-2026 WordPress site. Run 19's first pull reported "the sprint page has zero impressions in all three windows and is unknown to Google" — a faithful report of a different property, which would have produced a false run-4 verdict. **Pass `siteUrl: "sc-domain:wescalestartups.com"` on every call, and sanity-check the returned URLs first: WordPress paths (`/seo-services/`, `/portfolio/*`) mean you are on the wrong property.**
- **GSC MCP `row_limit` defaults to 100 and silently truncates.** Rows return clicks-desc, then zero-click rows **alphabetically by (page, query)** — a low limit guillotines everything after roughly `/f…`. **Always pass `row_limit: 25000`**, which returns the whole dataset in one call.
- Large GSC pulls exceed the tool output limit. Run them in a **subagent** with an explicit list of the figures you want back — **and an explicit `siteUrl`, plus an instruction to abort if the returned paths look wrong.**
- 60–89% of a page's impressions — and ~68% of the site's clicks — are **anonymised** by Google (rare, personally-phrased queries). That gap is itself a signal and it skews heavily conversational.
- **GSC MCP: recrawl comes via the sitemap.** `indexing_submit` / `indexing_status` untested (prohibition 18). **`genai_query_insights` is NOT an AI-citation report** — heuristic pattern-matching on ordinary query data by its own caveat. **Never quote it as citation evidence.** It is the best way to isolate the conversational set: **33 of 343 queries, 671 impressions, zero clicks, 21 of them on `/fractional-cmo-vs-agency`** — which with the AI report and the panel makes **three instruments saying that page attracts the right questions and converts none in classic search.** Its value lives outside classic rank; that is not an argument for a third rewrite.
- **Two phantom `legacy_*` accounts appear when the extension's optional `user_config` fields are blank** — the app passes the literal `${user_config...}` string through as an env var and the server registers it as a credential source, breaking every call with `Multiple google accounts found`. **Remove them with `accounts_manage remove`; do not fill the fields in.** Working auth is browser OAuth.
- **A connector reporting "unavailable" is a symptom, not a diagnosis. Run the server and read its stderr before writing down a cause.** Runs 17 and 18 both carried "Daniel must re-authorise Search Console" as fact without once executing the binary; the real fault was `search-console-mcp` shipping without its `node_modules` and crashing on `import dotenv`. `npm install --omit=dev` in the extension directory fixed it, with no credential change. **Extension `node_modules` are wiped by any reinstall or update** — same trap as the Bing extension's vendored date patch. **If either connector dies again, check for `node_modules` first.**
- **Bing MCP date endpoints were patched 2026-08-25** (`parse_timestamp_from_api` returned a naive datetime; fixed with `tz=timezone.utc` in the vendored lib). **A reinstall wipes the patch.** Backup: `utils.py.bak`.
- **Bing quirks:** query stats are weekly buckets dated to Fridays covering ~36% of impressions — never compare to GSC dailies. Backlinks must be read from the UI (`GetLinkCounts` returns empty). Tools need `self="bing"`. **Quota is 100/day and 100/month**; `submit_url` returns `null` on success. Crawl-issue data is **historical** — re-check live before acting. Bing's site URL is `https://wescalestartups.com`; `sc-domain:` returns `InvalidUrl`.
- Cloudflare MCP has no Pages-deployment tools; verify deploys by fetching the live URL with a cache-buster.
- **curl works fine against the site** for status codes and redirect chains, despite the SKILL note about bot challenges. **Trust curl status codes over `web_fetch` bodies when checking redirects.**

## Standing decisions

- **Every commit boundary must be a state that builds.** If a change spans files, push the files together.
- **Verify twice: the tree you are about to push, then the tree you pushed.** Before the commit — clone, `npm ci`, apply, `npm run build` + `astro check`, inspect rendered `dist`. After the push — fetch `origin/main`, rebuild from it, re-run `check:lastmod`, and re-check the sitemap arithmetic. `check:lastmod` is structurally incapable of failing before the content commit exists (Trap 5), so the second pass is the only one that means anything for it.
- **Noindexing a static page is a two-file change.** `src/pages/sitemap.xml.ts` keeps a hand-maintained static-path list, so `metaRobots="noindex"` alone leaves a sitemap advertising a noindex URL. Change both, then check the arithmetic: **pages built − noindexed = sitemap `<loc>` count.**
- **Sitemap lastmod is generated, not hand-edited.** Two-step: commit the content, then `npm run refresh:lastmod` and commit the result. Applies to any route listed in `src/lastmod.ts` — static pages, service/case content, and the four `/insights/*` pillars. `grep` the route rather than assuming.
- Prefer content-only commits; avoid layout/CSS the bot can't visually verify. Reusing an existing component on an existing code path is fine; adding a page to a template's special-case list is not worth it if the same text already renders elsewhere in the DOM.
- Always fetch the live URL post-deploy before declaring success, and re-test that new redirect rules did not shadow existing specific ones.
- Never state unsourced market statistics. Anchor cost claims on WSS's published ranges and reuse the bands on `/insights/fractional-cmo-cost-uk` rather than minting new ones.
- **Keep the "point them somewhere better" voice.** Every comparison should name the case where a competitor or a different model is the right buy. It is the brand voice *and* what makes a passage worth citing.
- **When a change is defensible under two competing readings of the data, prefer it** over one needing the ambiguity resolved first.
- **Sweep the connectors before writing anything that implies WSS expertise or client work.** The VC guide was written assuming fund-side experience; Granola, Notion, Gmail and Drive established there is none. The real position is accelerator-side (Google for Startups, DeepMind, Techstars, GrowthMentor, several hundred founder sessions). **That check stopped an unsupportable claim reaching a public page. Do it every time.**
- **A hub page must not restate its spokes.** Run 3 spent a whole run undoing a self-competing cluster; do not rebuild one.
- **`src/data/growthTools.ts` is the primary source for what the free tools do — not any page that describes them.** Runs 13 and 14 both got this wrong. The Growth Bottleneck Scorecard is **12 questions, ~4 minutes**, scoring **founder dependency** — a different question from the five-layer framework on `/diagnose`. Never describe either in terms of the other.
- **Push large files through a subagent that reads and pushes them itself**, running `git hash-object` on the sandbox file and checking the returned blob SHA matches. The bytes never enter the parent's context and corruption becomes detectable rather than silent. Run 19 did both its files this way. This is the practical answer to Trap 4.
- **Judge a page from its rendered HTML, never from source-file size or a source grep.** Run 13 nearly noindexed `/when-growth-plateaus` after grepping its `.astro` file and finding no headings — it uses `StrategicPage`, which supplies them. **Measure `dist/*.html` or the live URL**, including page-depth percentages.
- **Verify claims about the site against the site, not against this file.** **Five false facts have been found here** — an invented robots.txt reversal repeated across four runs; a "Bing reports zero inbound links" line left three bullets below its own correction; an `/insights/*` lastmod exemption that put CI red in run 9; a research-insight slug kept from before a rename; and (run 19) **"`/facts/*` carry `lastUpdated`" — a maintenance instruction structurally impossible to perform, because neither page passed the prop.** Same shape every time: a half-truth never re-checked against the primary source, and the fifth had been *acted on* for eight runs. **`grep` the repo or fetch the live URL before acting on any claim in here — and when you correct one, DELETE the wrong line rather than annotating it.**
- Mark confidence explicitly (verified / inferred / vendor-sourced). Most GEO research is published by companies selling GEO tools.
