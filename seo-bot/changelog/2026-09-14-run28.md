**Trap 9 as written says `["date"]` returns the correct property and is the fallback when `["page"]` is poisoned.** That is no longer true. **So the discriminator still detects the fault, but there is no longer a dimension to fall back to.** And the documented fallback *to* the fallback — the Search Console UI through the browser — **is independently blocked by the account mismatch.**

**Net: both routes to search data are closed simultaneously, for two unrelated reasons. That has not happened before.** Run 27 had a working API and a blocked UI; run 26 had a working API and no browser. **This run has neither.**

### 1b. It broke within 90 minutes, between two runs on the same day

**Nothing about the site, the property or the credentials changed in between. The only thing that changed is the MCP server instance.** That points at per-instance property resolution — the same class of defect as Trap 11, which also derives state at server start. **It is not diagnosed, and per the standing instruction it will not be: the instruction is to run the discriminator and move on.** But the appear/disappear pattern is now observed twice with no intervention either time, so **"repaired" was always too strong a word for what run 26 established.** Run 26 verified it working; it did not establish that it would stay working.

**Amend the playbook's language from repaired to intermittent, and check every run.** That is done below.

## 3. THE DEFECT: `/services/90-day-growth-sprint` contradicts itself on the experiment count

| Where | Says | Byte offset (of 101,594) |

**Seven statements of 6–8, one of 3–5, on one page, for one £8k–£12k engagement.** The source of the outlier is `src/content/services/90-day-growth-sprint.json:15`, rendered through `[slug].astro:507`. **A buyer reads "Ship 6–8 targeted experiments" in the hero and "Select 3–5 experiments" further down.**

**Which is canonical: 6–8.** It carries the schema, the meta description, the hero and the AI summary. The JSON `process` bullet is the defect.

**And the fix must be surgical, because a careless harmonisation would introduce a new error.** `src/pages/first-30-days.astro:63` also says *"3–5 experiments shipped"* — **that one is CORRECT**: it describes month one, not the twelve weeks. **Change the service JSON only. Do not touch `first-30-days`.**

**Why the AI channel has not surfaced this:** every 6–8 statement sits in the first 30% of the document; the 3–5 sits at **34%**, just outside the band that supplies most AI Overview citations. That is consistent with prompt 3 reporting 6–8 correctly for three consecutive readings — **the citation-weighted copy is the correct copy, by luck rather than design.**

### Why it was NOT shipped

**Prohibition 19.** Run 15's verdict falls **2026-09-17 — three days away** — and is judged on *"whether the new URL takes the queries off the £8k–£12k service page"*. **That service page is this page.** Editing its body copy three days before the verdict puts a change inside the measurement.

A single numeral in one body bullet almost certainly cannot reallocate queries between two URLs. **But "almost certainly" is an inference, and prohibition 19 is categorical precisely because this bot's inferences about what confounds what have been wrong before.** The defect has been live a long time, is currently causing no measurable harm, and costs nothing to leave for three more days. **The verdict has been waited weeks for and unblocks backlog 15.
