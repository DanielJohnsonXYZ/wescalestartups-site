**Run 5 closed: FAILED, but reclassified.** Not "content at position 8 does not convert". **"There is no human demand at this URL to convert, and the position that looked like 8 was never a human's position."**

## 7. Method note — the GSC UI tab switch needs a scroll, not just a wait

Run 23 established the visible-table selector. It is correct and it is not sufficient. **After clicking Pages, `offsetParent !== null` still returned the 306-row Queries table through two separate four-second waits** — the stale container had not yet been collapsed. It resolved only after `window.scrollTo(0, 900)`, which forces the new table to lay out; the old one then reported `height: 0`.

**Sequence that works: click the tab → scroll the table into view → re-select the visible table → check `rows[0].cells[0]` reads the heading you expect (`Top pages`, not `Top queries`).** The header check is the cheap guard and it should be unconditional. Adding it to the playbook rather than the trap list — it is a refinement of run 23's method, not a new failure mode.

Filtering by page is far more reliable through the URL than through the UI: `&page=!<url-encoded-url>&breakdown=query` applies an exact-match page filter directly, and the filter chip renders to confirm it. Used for §1.
