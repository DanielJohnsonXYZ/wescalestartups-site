## 2. Four orphan pages, four different answers

Run 12's audit found four indexable pages with **zero inbound internal links**. The
temptation is to treat "orphan" as a single diagnosis with a single fix. It isn't.
An orphan page is a page nobody chose to link to, and the useful question is *why
not*.

| Page | Verdict | Why |
|---|---|---|
| `/seo-content-strategy` | **Link it** | Topic clusters, buyer-stage mapping, conversion paths. Substantive. |
| `/when-growth-plateaus` | **Link it** | Three sections plus an FAQ. Substantive. |
| `/wss-scale-score` | **Link it** | A working diagnostic tool scoring eight dimensions. |
| `/wss-calendar` | **Noindex it** | Headings are "What WSS Calendar does" and "Privacy and terms". |

### The mistake I nearly made

I first assessed `/when-growth-plateaus` by grepping its source file for headings.
It had none, so I wrote it off as thin and queued it for noindex.

It uses the `StrategicPage` component, which supplies the headings. The **rendered**
page has three substantive sections and an FAQ block. The grep was measuring the
wrong artefact.

> **Rule, added to the playbook:** judge page quality from built or live HTML, never
> from source-file size or a source grep. On a component-driven site the source file
> is not the page. This is the second time this exact class of error has appeared —
> run 12 had it too.

### `/wss-calendar` — noindexing is a two-file job here

The page has to stay live and reachable: Google's OAuth verification for the
scheduling app requires a working privacy URL. So `noindex,follow`, not removal, and
not `nofollow`.

But `src/pages/sitemap.xml.ts` keeps a **hand-maintained** list of static paths.
Setting `metaRobots` on the page does not remove it from the sitemap, and a sitemap
that advertises a noindex URL is a contradictory signal. Both files had to change.

After: 117 pages built, 11 noindexed, **106 indexable, 106 in the sitemap**. The
arithmetic closes exactly, which is the check worth running after any noindex.

### Where the links went

Not scattered — placed where a reader would actually follow them:

- `/seo-content-strategy` ← **AI-native GTM pillar.** That page already routes
  readers to "make AI search visibility citable" for the technical layer; the
  content-strategy page is the layer between the two.
- `/when-growth-plateaus` and `/wss-scale-score` ← **bottlenecks pillar.** The
  plateau page is the same problem in founder language; the Scale Score scores eight
  dimensions where `/diagnose` scores five.

Link text labels the *difference* in each case, so the two scorecards don't read as
duplicates of each other. A link from a pillar that has traffic is worth more than
one from a page nobody reaches — which is the whole reason these were orphans.

## 4. Traps confirmed, and one new quirk

**Trap 5 held.** `check:lastmod` resolves each route to the last *git commit*
touching its backing file, so it cannot pass before the content commit exists. Ran
the two-step in the right order: content first, then `refresh:lastmod`, then commit
the result. Green on the pushed tree.

**Guessing a blob SHA fails.** Abbreviated `e54b449` expanded to a fabricated
40-char SHA, and the write was rejected as stale. Correct move each time: fetch the
real SHA with `get_file_contents` rather than reconstruct it. The rejection was the
system working — a fabricated SHA that *happened* to collide would have overwritten
someone else's change silently.

**New, minor:** `refresh-lastmod.mjs` writes dates in the runner's local timezone. A
commit at 23:40 UTC on the 26th became `2026-08-27` under BST. Harmless for
`/insights/*` because the sitemap takes those dates from frontmatter `updatedAt`,
not from this map — but it means the `/insights/*` entries in
`staticPathLastModified` are dead weight for sitemap purposes. Not worth a fix
today; worth knowing before someone debugs a one-day discrepancy.
