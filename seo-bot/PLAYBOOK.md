## Connector and environment notes

- **The sandbox can clone, install and build the repo.** `git clone` + `npm ci` (~22s) + `npm run build` (~3s after OG generation) all work; the GitHub connector pushes. **Verify every change this way before committing** — build, `astro check`, JSON-LD parsing, rendered HTML and internal-link targets, all before the commit exists.
  - Trap 1: `git clone` writes ~10,000 lines of output and will blow the tool's token limit. Redirect everything to a log file and `tail -c` it.
  - Trap 2: **a shallow clone breaks `refresh:lastmod`** — with `--depth 1` every file resolves to the clone date and the script rewrites all 78 routes. Use `git fetch --unshallow` first. (Same reason CI needs `fetch-depth: 0`.)
  - Trap 3: cloned files are read-only to `rm -rf`; use a fresh directory name rather than deleting.
  - Trap 4: **no git credentials in the sandbox.** Every write goes through the GitHub connector, which replaces whole files, so a large append-only file cannot be safely appended to — re-emitting 40KB from context risks silent corruption. **This is why the changelog is split per run. Keep it that way.**
  - Trap 5: **`check:lastmod` cannot be verified before the content commit exists, and a green result pre-commit means nothing.** The script resolves each route to the last *git commit* touching its backing file. Run against a sandbox tree where the file is modified but uncommitted, a stale route still resolves to its old date and the check passes. It only goes red once the content lands. **Always re-run `check:lastmod` against the pushed tree**, and expect to need the second half of the two-step.
  - Trap 6: **the GitHub connector rejects an abbreviated or reconstructed blob SHA.** Expanding `e54b449` into a plausible 40-character string fails as stale, which is the system working. Always fetch the real SHA with `get_file_contents` (or `git rev-parse HEAD:path` against a freshly fetched tree) immediately before writing. Never reconstruct one.
  - Trap 7: **`refresh-lastmod.mjs` writes dates in the runner's local timezone** — a one-day discrepancy is harmless, do not debug it. On **shared dynamic routes it cannot tell which slug changed**: editing one service bumps all four `/services/*`. Harmless, but never read a `/services/*` lastmod as evidence that page changed.
  - Trap 8: **`web_fetch` can return an empty body for a live, working page on this site.** Run 15 got three empty responses for a freshly deployed URL while `web_fetch` of `/sitemap.xml` on the same host worked normally. The page was fine — the Chrome connector returned the full article. Never treat an empty `web_fetch` as evidence a page is broken, and never revert a commit on that basis. Confirm through the Chrome connector or the deployed `sitemap.xml` first.
- **`staticPathLastModified` covers 82 routes including SOME `/insights/*`** — the four pillars (`what-is-a-fractional-cmo`, `b2b-saas-gtm-strategy`, `ai-native-gtm`, `startup-growth-bottlenecks`) plus `/insights` and `/insights/glossary`. Every other insight falls back to `siteConfig.siteLastModified`. **So the sitemap two-step DOES apply to the pillars**, and to static pages and service/case content. Runs 5–8 recorded the opposite and run 9 left CI red trusting it. **Do not guess: `grep` the route in `src/lastmod.ts`.**
- **GSC MCP `row_limit` defaults to 100 and silently truncates.** Rows return clicks-desc, then zero-click rows **alphabetically by (page, query)** — a low limit guillotines everything after roughly `/f…`. **Always pass `row_limit: 25000`**, which returns the whole dataset in one call.
- Large GSC pulls exceed the tool output limit. Run them in a **subagent** with an explicit list of the figures you want back, so the dump stays out of main context.
- 60–89% of a page's impressions — and **68% of the site's clicks** — are **anonymised** by Google (rare, personally-phrased queries). Some pages are at 100%. That gap is itself a signal and it skews heavily conversational.
- GSC MCP is read/inspect only — no request-indexing endpoint. Recrawl comes via the sitemap. (The **UI** has more than the connector — see the Generative AI bullet.)
- **Bing MCP date endpoints were patched 2026-08-25** (`parse_timestamp_from_api` returned a naive datetime, failing RFC 3339 validation; fixed with `tz=timezone.utc` in the vendored lib). Query/page/rank/url-info endpoints work now. **A reinstall of the extension wipes this patch** — that is why they would start erroring again. Backup: `utils.py.bak`.
- **Bing quirks:** query stats are weekly buckets dated to Fridays covering ~36% of impressions — never compare to GSC dailies. Backlinks must be read from the UI (`GetLinkCounts` returns empty regardless). Tools need the `self="bing"` arg. Quota 100/day, 600/month; `submit_url` returns `null` on success. Crawl-issue data is **historical** and still lists URLs fixed weeks ago — re-check live before acting.
- Cloudflare MCP has no Pages-deployment tools; verify deploys by fetching the live URL with a cache-busting query string.
- **curl works fine against the site** for status codes and redirect chains, despite the SKILL note about bot challenges. **Trust curl status codes over `web_fetch` bodies when checking redirects.**

## Standing decisions

- **Every commit boundary must be a state that builds.** If a change spans files, push the files together.
- **Verify the build against the tree you pushed, not the tree you have locally.** Since run 5, do this in the sandbox: clone, `npm ci`, apply the change, `npm run build` + `astro check`, and inspect the rendered `dist` HTML — *before* the commit exists.
- **Then verify again AFTER the push.** Fetch `origin/main`, rebuild from it, and re-run `check:lastmod`. Some checks — `check:lastmod` above all — are structurally incapable of failing before the commit exists (Trap 5). A run is not finished until the pushed tree has been built and checked.
- **Noindexing a static page is a two-file change.** `src/pages/sitemap.xml.ts` keeps a hand-maintained static-path list, so `metaRobots="noindex"` alone leaves a sitemap advertising a noindex URL. Change both, then check the arithmetic: **pages built − noindexed = sitemap `<loc>` count.**
- **Sitemap lastmod is generated, not hand-edited.** Two-step: commit the content, then `npm run refresh:lastmod` and commit the result. Applies to any route listed in `src/lastmod.ts` — static pages, service/case content, and the four `/insights/*` pillars. `grep` the route rather than assuming.
- Prefer content-only commits; avoid layout/CSS the bot can't visually verify. Reusing an existing component on an existing code path is fine; adding a page to a template's special-case list is not worth it if the same text already renders elsewhere in the DOM.
- Always fetch the live URL post-deploy before declaring success, and re-test that new redirect rules did not shadow existing specific ones.
- Never state unsourced market statistics. Anchor cost claims on WSS's published ranges and reuse the bands on `/insights/fractional-cmo-cost-uk` rather than minting new ones.
- **Keep the "point them somewhere better" voice.** Every comparison should name the case where a competitor or a different model is the right buy. It is the brand voice *and* what makes a passage worth citing.
- **When a change is defensible under two competing readings of the data, prefer it** over one needing the ambiguity resolved first.
- **Sweep the connectors before writing anything that implies WSS expertise or client work.** The VC guide was written assuming fund-side experience; Granola, Notion, Gmail and Drive established there is none — every named fund is a cold prospect. The real position is accelerator-side (Google for Startups, DeepMind, Techstars, GrowthMentor, several hundred founder sessions). **That check stopped an unsupportable claim reaching a public page.** Do it every time.
- **A hub page must not restate its spokes.** Run 9's pillar owns definition and scope only and summarises-and-links the rest. Run 3 spent a whole run undoing a self-competing cluster; do not rebuild one.
- **`src/data/growthTools.ts` is the primary source for what the free tools do — not any page that describes them.** Runs 13 and 14 both got this wrong. The Growth Bottleneck Scorecard is **12 questions, ~4 minutes**, scoring **founder dependency** — a different question from the five-layer framework on `/diagnose`. Two instruments, two questions; never describe either in terms of the other.
- **Push large files through a subagent that reads and pushes them itself.** Run 14 moved the 49 KB `src/pages/services/[slug].astro` this way: the subagent runs `git hash-object` on the sandbox file, pushes it, then checks the returned blob SHA matches. The bytes never enter the parent's context and corruption becomes detectable rather than silent. This is the practical answer to Trap 4 for anything large.
- **Judge a page from its rendered HTML, never from source-file size or a source grep.** Run 13 nearly noindexed `/when-growth-plateaus` after grepping its `.astro` file and finding no headings — it uses `StrategicPage`, which supplies them. On a component-driven site the source file is not the page. Measure `dist/*.html` or the live URL.
- **Verify claims about the site against the site, not against this file.** Three false facts have now been found here: an invented robots.txt reversal repeated across four runs, a "Bing reports zero inbound links" line left in place three bullets below the correction that disproved it, and the `/insights/*` lastmod exemption that put CI red in run 9. **The pattern in all three is a half-truth that was never re-checked against the primary source.** Before acting on any factual claim in this file, `grep` the repo or fetch the live URL — and when you correct something, **delete the wrong line** rather than adding a corrected one next to it.
- Mark confidence explicitly (🟢 verified / 🟡 inferred / 🔴 vendor-sourced). Most GEO research is published by companies selling GEO tools.
