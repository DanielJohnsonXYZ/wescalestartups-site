## 1. THE API'S WRONG-PROPERTY BUG IS NOT THE PHANTOM ACCOUNTS. Run 21 left this explicitly untested; it is now settled.

Run 21 recorded: *"Whether removing the phantom accounts caused this is unknown and untested — do not assume the removal caused it."*

This run tested it in the only order that answers the question: **removed `legacy_google` and `legacy_bing` FIRST, then pulled `dimensions: ["page"]` with `siteUrl: "sc-domain:wescalestartups.com"`.** Result was identical to run 21's — a single row, `https://www.wescalestartups.com/`, 1 impression, against a real 6,270.

**Two independent faults, not one.** The phantoms break authentication; the dimension bug misroutes the query to the stale WordPress URL-prefix property. Clearing the first does nothing for the second. **A future run must not expect the removal to restore page- or query-level data, and must not read a successful `accounts_manage remove` as a green light to trust `["page"]`.**

This matters beyond bookkeeping: run 21's addendum found "one cause, four symptoms" and was right about Bing. The temptation was to extend that unification to the dimension bug as well. **It does not extend. One correct unification does not license the next one.**

## 2. THE FIX: the Search Console UI is a complete page- and query-level instrument, read through the DOM

The playbook said "if it is still broken, read the Search Console UI in the browser." That was a gesture, not a method. It is now a method, and it fully replaces the broken API dimensions.

**Two hazards, both hit this run.**

**(a) `get_page_text` is actively misleading on this page.** It returned the **3-month** query table — 692 rows, `we scale startups` at 38 clicks / 412 impressions — while the screen showed the **28-day** view and the header read 61 clicks. Twice, including once immediately after clicking through to a different tab. **This run came within one paragraph of logging 3-month figures as a 28-day window**, and only caught it because 38 brand clicks is implausible for 28 days against a ~24-click history.

The cause, confirmed: `document.querySelectorAll('[role="tab"]')` returns **twelve** tabs, i.e. two complete tablists — one orphaned stale container and one live. `get_page_text` grabs the first. **This is Trap 8's family — never treat a stale or partial read as a measurement — in a form no previous run met.**

**(b) The reliable route is `javascript_tool` over `document.querySelectorAll('table')`.** Tables come back in load order; **the last one is the live view**, earlier ones are stale renders of previously-selected ranges. Strip `Copy URL to clipboard|Open in new tab|Inspect URL` from page rows. One call returns the whole table — 337 queries at 28d, 692 at 90d, 91 pages — with no truncation and no `row_limit` guillotine.

**The Generative AI report is at `/performance/search-analytics/ai?resource_id=…`.** The `search_appearance=GENERATIVE_AI` URL parameter does not apply the filter and the in-page "Open report" link did not navigate on click. Go to the path.
