## Connector and environment notes

- **The sandbox can clone, install and build the repo.** This corrects run 4's playbook, which said only Daniel's local clone could. `git clone` + `npm ci` (~22s) + `npm run build` (116 pages, ~3s after OG generation) all work, and the GitHub connector pushes. **Verify every change this way before committing** — run 5 confirmed build, `astro check`, JSON-LD parsing, rendered HTML and internal-link targets before the commit existed.
  - Trap 1: `git clone` writes ~10,000 lines of output and will blow the tool's token limit. Redirect everything to a log file and `tail -c` it.
  - Trap 2: **a shallow clone breaks `refresh:lastmod`** — with `--depth 1` every file resolves to the clone date and the script rewrites all 78 routes. Use `git fetch --unshallow` first. (Same reason CI needs `fetch-depth: 0`.)
  - Trap 3: cloned files are read-only to `rm -rf`; use a fresh directory name rather than deleting.
  - Trap 4: **there are no git credentials in the sandbox.** You can clone and build, but every write goes through the GitHub connector, which replaces whole files. That means a large append-only file like CHANGELOG.md has to be re-emitted in full to add one entry. Read it completely before rewriting it, and diff the pushed result against the sandbox copy afterwards.
- **`/insights/*` routes are NOT in `staticPathLastModified`.** They fall back to `siteConfig.siteLastModified`, so **the sitemap two-step does not apply to insights content changes** — `check:lastmod` will be green with zero routes updated. The two-step still applies to static pages and service/case content.
- **GSC MCP `row_limit` is yours to set and the default (100) silently truncates.** Rows come back clicks-desc first, then **zero-click rows sorted alphabetically by (page, query)** — a low limit guillotines everything after roughly `/f…`. Always pass `row_limit: 25000`. `dimensions: "page,query"` at that limit returns the whole 819-row dataset in one call.
- Large GSC pulls exceed the tool output limit. Run them in a **subagent** with an explicit list of the figures you want back, so the dump stays out of main context.
- 60–89% of a page's impressions can be **anonymised** by Google (rare, personally-phrased queries). Named-query impressions will not reconcile to page-level totals. That gap is itself a signal: it skews heavily conversational. Some pages are at 100% — see the `page` vs `page,query` bullet above.
- GSC MCP is read/inspect only — no request-indexing endpoint. Recrawl comes via the sitemap.
- **Bing MCP date endpoints were fixed 2026-08-25** — `parse_timestamp_from_api` returned a naive datetime, failing FastMCP's RFC 3339 `date-time` output validation. Patched to `tz=timezone.utc` in the vendored lib. `get_query_stats`, `get_page_stats`, `get_rank_and_traffic_stats`, `get_url_info` all work now. **A reinstall of the extension wipes this patch** — if those endpoints start erroring again, that is why. Backup: `utils.py.bak`.
- Bing query stats are **weekly buckets dated to Fridays**, and cover only ~36% of impressions (the rest are privacy-filtered). Do not compare directly against GSC dailies.
- Bing's Backlinks UI report and the `GetLinkCounts` API method are different data products; the API returns empty regardless. Read backlinks from the UI.
- Bing MCP tools need the `self="bing"` arg quirk. Quota is 100/day, 600/month. **Bing query/page/rank-stats endpoints are broken** (schema validation error on returned dates); crawl issues, quota, link counts and URL submission work. `submit_url` returns `null` on success.
- **Bing crawl-issue data is historical, not current.** It still lists URLs fixed weeks ago. Always re-check live before acting on it.
- Cloudflare MCP has no Pages-deployment tools; verify deploys by fetching the live URL with a cache-busting query string.
- **`mcp__workspace__bash` curl works fine against the site** for status codes and redirect chains, despite the SKILL note about bot challenges. `web_fetch` sometimes returns a stale cached body — **trust curl status codes over web_fetch bodies when checking redirects.**

## Standing decisions

- **Every commit boundary must be a state that builds.** If a change spans files, push the files together.
- **Verify the build against the tree you pushed, not the tree you have locally.** Since run 5, do this in the sandbox: clone, `npm ci`, apply the change, `npm run build` + `astro check`, and inspect the rendered `dist` HTML — *before* the commit exists.
- **Sitemap lastmod is generated, not hand-edited.** Two-step on static/service/case content: commit the content, then `npm run refresh:lastmod` and commit the result. Does not apply to `/insights/*` (see connector notes).
- Prefer content-only commits; avoid layout/CSS the bot can't visually verify. Reusing an existing component on an existing code path is fine; adding a page to a template's special-case list is not worth it if the same text already renders elsewhere in the DOM.
- Always fetch the live URL post-deploy before declaring success, and re-test that new redirect rules did not shadow existing specific ones.
- Never state market statistics that aren't sourced; anchor cost claims on WSS's own published ranges, and reuse the bands already published on `/insights/fractional-cmo-cost-uk` rather than minting new ones.
- **Keep the "point them somewhere better" voice.** Every comparison the site publishes should name the case where a competitor or a different model is the right buy. It is the brand voice and it is also what makes a passage worth citing.
- **When a change is defensible under two competing readings of the data, prefer it** over one that requires the ambiguity to be resolved first.
- **Sweep the connectors before writing anything that implies WSS expertise or client work.** Writing the VC guide, the assumption going in was that WSS had some fund-side work to draw on. Granola, Notion, Gmail and Drive established it has none — every named fund is a cold prospect, and there are no recorded fund or LP meetings. The real position is accelerator-side (Google for Startups, DeepMind, Techstars, GrowthMentor, several hundred founder sessions). **That check is what stopped an unsupportable claim reaching a public page.** Do it every time, and note what the sweep says is confidential.
- **A hub page must not restate its spokes.** Run 9's pillar owns definition and scope only, and summarises-and-links on timing, cost and the agency comparison. Run 3 spent a whole run undoing a cluster that competed with itself; do not rebuild one.
- **Verify claims about the site against the site, not against this file.** The 2026-08-25 audit found two false facts here: an invented robots.txt reversal repeated across four runs, and a "Bing reports zero inbound links" line left in place three bullets below the correction that disproved it. A self-maintained memory file drifts. Before acting on any factual claim in it, re-check the primary source — and when you correct something, **delete the wrong line** rather than adding a corrected one next to it.
- Mark confidence explicitly (🟢 verified / 🟡 inferred / 🔴 vendor-sourced). Most GEO research is published by companies selling GEO tools.
