## Connector and environment notes

- **The sandbox can clone, install and build the repo.** `git clone` + `npm ci` (~22s) + `npm run build` (~3s) all work; the GitHub connector pushes. **Verify every change this way before committing. Traps 1–8 are in the task file's FIXED RULES — do not restate them here.** The three that have cost real time: **Trap 2** (shallow clone makes `refresh:lastmod` rewrite all routes), **Trap 5** (a green pre-push `check:lastmod` means nothing), **Trap 8** (never revert on an empty `web_fetch`, and never record an empty or truncated fetch as an absence of anything).
- **`staticPathLastModified` covers 83 routes including SOME `/insights/*`** — the four pillars, `/insights` and `/insights/glossary`; every other insight falls back to `siteConfig.siteLastModified`. **So the sitemap two-step DOES apply to the pillars**, to static pages, and to service/case content. Runs 5–8 recorded the opposite and run 9 left CI red trusting it. **Do not guess: `grep` the route.** **The script only refreshes routes already in the map — it never adds one**; insert a placeholder key and let `refresh:lastmod` write the real date.
- **GSC MCP `analytics_query` SILENTLY ANSWERS ABOUT THE WRONG PROPERTY IF `siteUrl` IS OMITTED. It does not error.** The account holds 31 sites including a stale `https://www.wescalestartups.com/` URL-prefix property from the pre-May-2026 WordPress site; run 19's first pull nearly produced a false verdict from it. **Pass `siteUrl: "sc-domain:wescalestartups.com"` on every call, and sanity-check the returned URLs first: WordPress paths (`/seo-services/`, `/portfolio/*`) mean you are on the wrong property.**
- **GSC MCP `row_limit` defaults to 100 and silently truncates.** Rows return clicks-desc, then zero-click rows **alphabetically by (page, query)** — a low limit guillotines everything after roughly `/f…`. **Always pass `row_limit: 25000`**, which returns the whole dataset in one call.
- Large GSC pulls exceed the tool output limit. Run them in a **subagent** with an explicit list of the figures you want back — **and an explicit `siteUrl`, plus an instruction to abort if the returned paths look wrong.**
- 60–89% of a page's impressions, and ~68% of clicks, are **anonymised** by Google. The gap is itself a signal and skews conversational.
- **GSC MCP: recrawl comes via the sitemap.** `indexing_submit` / `indexing_status` untested (prohibition 18). **`genai_query_insights` is NOT an AI-citation report** — heuristic pattern-matching on ordinary query data, by its own caveat. **Never quote it as citation evidence.** Its real use is isolating the conversational set: **33 of 343 queries, 671 impressions, zero clicks, 21 on `/fractional-cmo-vs-agency`** — with the AI report and the panel, **three instruments saying that page attracts the right questions and converts none in classic search.** Not an argument for a third rewrite.
- **Two phantom `legacy_*` accounts break every call with `Multiple google accounts found` — and they killed BOTH GSC and Bing in run 21 (`InvalidApiKey` was the Bing phantom, not a Bing fault). ROOT CAUSE (`dist/common/auth/config.js`): the extension re-derives them from env vars at EVERY server start — `legacy_google` from `GOOGLE_APPLICATION_CREDENTIALS` or `GOOGLE_CLIENT_EMAIL`+`GOOGLE_PRIVATE_KEY`, `legacy_bing` from `BING_API_KEY` — so `accounts_manage remove` deletes from saved config and the next launch recreates it. Blank optional fields arrive as the literal `${user_config…}` string, which is truthy, so "do not fill the fields in" NAMES THE CAUSE AS THE CURE.** Clean fix = reinstall without those fields; practical fix = the `accounts_manage` allow-rule so a run heals itself. Detail: `changelog/2026-09-02-run21.md` §B.
- **A connector fault and a permission denial look identical from inside a run, and are not the same thing.** Run 18's rule was written about a server that would not start. Run 21 met the other kind: a working server, an operation that exists, and an authorisation layer refusing it — `accounts_manage remove`, `tabs_context_mcp` and `preview_start` were all denied by the classifier, not by the tool. **Distinguish them, and report a denial to Daniel as an ask rather than logging it as an outage.**
- **AN UNATTENDED RUN CANNOT USE A BROWSER AT ALL — refused because nobody is there to approve, not because anything is broken.** That removes the AI panel and the UI-only Generative AI report from every scheduled run. **A reading that could not be taken is null: never log it as a low share.** **Resolved 2026-09-02: schedule moved to Mon/Wed/Fri 09:30 so runs are ATTENDED**, rather than giving an unattended agent Daniel's signed-in Chrome — a poor trade for a bot that reads competitor pages. **If a run finds itself unattended, expect no browser and plan a repo-and-build run.**
- **CHECK THE INSTRUMENTS AT THE TOP OF THE RUN, NOT MID-FLIGHT.** One `accounts_manage list` and one browser context call cost nothing and determine what kind of run is possible. Run 21 planned around GSC and the panel and found mid-run that neither existed.
- **A connector reporting "unavailable" is a symptom, not a diagnosis — run the server and read its stderr before writing down a cause.** Runs 17–18 carried "Daniel must re-authorise Search Console" as fact without once executing the binary; the real fault was missing `node_modules`. **Extension `node_modules` are wiped by any reinstall** — check for them first. **And distinguish a broken instrument from a run that is FORBIDDEN to use one (run 21): they present identically and need opposite responses — a bug to diagnose vs a permission to request.**
- **Bing MCP date endpoints were patched 2026-08-25** (`parse_timestamp_from_api` returned a naive datetime; fixed with `tz=timezone.utc` in the vendored lib). **A reinstall wipes the patch.** Backup: `utils.py.bak`.
- **Bing quirks:** query stats are weekly buckets dated to Fridays covering ~36% of impressions — never compare to GSC dailies. Backlinks must be read from the UI (`GetLinkCounts` returns empty). Tools need `self="bing"`. **Quota is 100/day and 100/month**; `submit_url` returns `null` on success. Crawl-issue data is **historical**. Site URL is `https://wescalestartups.com`; `sc-domain:` returns `InvalidUrl`. **Run 21's `InvalidApiKey` was NOT a Bing fault — it was the `legacy_bing` phantom, and removing it fixed Bing in the same stroke as GSC. One cause, four symptoms.**
- Cloudflare MCP has no Pages-deployment tools; verify deploys by fetching the live URL with a cache-buster.
- **curl works fine against the site** for status codes and redirect chains. **Trust curl status codes over `web_fetch` bodies when checking redirects.**

## Standing decisions

- **The verification protocol, the lastmod two-step, and the noindex two-file rule are stated in full in the task file's FIXED RULES. Do not restate them here.** The three that have actually cost time: `check:lastmod` cannot fail before the content commit exists (Trap 5), so only the post-push pass means anything; **pages built − noindexed = sitemap `<loc>` count**, checked after every structural change; and reusing an existing component on an existing code path is fine, but adding a page to a template's special-case list is not worth it if the text already renders elsewhere in the DOM.
- Never state unsourced market statistics. Anchor cost claims on WSS's published ranges and reuse the bands on `/insights/fractional-cmo-cost-uk`.
- **Keep the "point them somewhere better" voice.** Every comparison should name the case where a competitor or a different model is the right buy — brand voice *and* what makes a passage worth citing.
- **When a change is defensible under two competing readings of the data, prefer it** over one needing the ambiguity resolved first.
- **Sweep the connectors before writing anything implying WSS expertise or client work.** The VC guide assumed fund-side experience; there is none. The real position is accelerator-side (Google for Startups, DeepMind, Techstars, GrowthMentor, several hundred founder sessions) — **a mentoring relationship, not client work. Run 20 found a third party had collapsed that distinction off-site and run 21 found the site doing it on `/facts/daniel-johnson`. Do this check every time.**
- **A hub page must not restate its spokes.** Run 3 spent a run undoing a self-competing cluster; do not rebuild one.
- **`src/data/growthTools.ts` is the primary source for what the free tools do** — not any page describing them (runs 13 and 14 both got this wrong). The Scorecard is **12 questions, ~4 min**, scoring **founder dependency** — not the five-layer framework on `/diagnose`. Never describe either in terms of the other.
- **Push large files through a subagent that reads and pushes them itself**, running `git hash-object` on the sandbox file and checking the returned blob SHA matches. The bytes never enter the parent's context and corruption becomes detectable rather than silent. Runs 19 and 21 did every file this way. This is the practical answer to Trap 4.
- **Judge a page from its rendered HTML, never from source size or a source grep.** Run 13 nearly noindexed `/when-growth-plateaus` after grepping its `.astro` file for headings that `StrategicPage` supplies. **Measure `dist/*.html` or the live URL**, including page-depth percentages.
- **Verify claims about the site against the site, not against this file. Seven false facts have been found here** — an invented robots.txt reversal repeated across four runs; "Bing reports zero inbound links"; an `/insights/*` lastmod exemption that put CI red; a stale research slug; "`/facts/*` carry `lastUpdated`"; "the winnable surface is shrinking" (an artefact of reading a still-streaming page, which the file then told every run to report); and **(run 21) "do not fill the extension's config fields in" — a workaround written down as a fix, when blank IS the cause.** Same shape every time: never re-checked against the primary source. **`grep` the repo, fetch the live URL, or read the source before acting on anything in here — and when you correct one, DELETE the wrong line.**
