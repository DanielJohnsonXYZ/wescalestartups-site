## Method notes

- **Check which GA4 property you are reading. Twice.** Run 1 spent its first reads on another company's site and the numbers looked healthy.
- **Qualify from the invitee's own form answers, not from the domain.** "We aren't SaaS" in a notes field settles a case a domain lookup would have got wrong.
- **A booking is not a website conversion until you know how the invitee got the link.** Check Gmail for outbound from Daniel, and for the mentoring-platform and referral threads, before counting one. Josefina looked like a website booking until the MentorCruise thread turned up; Scott McKim looked like one until Daniel's own 08-31 approach to Ferrock turned up.
- **RECONCILE TWO BOOKING LEDGERS, NEVER ONE.** The Cal.com email feed and the Clarity `/book/thanks` `email=` list disagree, and the email feed is the one that loses bookings. Run 3 found three of ten missing from it. **The moment a source is described in this playbook as reliable, that is the source to check against a second one.** Fifteenth false fact, and the first this bot wrote about its own primary metric.
- **A same-day second run does not get a new window.** Run 3 fired twelve hours after run 2, so "the last complete 28 days" was byte-for-byte the same window. **Check the previous changelog's date before re-measuring, and if the window has not moved, say so and spend the run on instruments, corrections and unanswered questions instead of re-reading the same numbers.**
- **A window that moves forward by a day is not a new measurement.** Run 2's 7 → 8 is one addition, not growth. Say so, or the next run reads a trend into it.
- **An empty container is not a broken embed.** The Cal.com widget renders nothing until scrolled near. Inspect the DOM before calling a blank screen a defect.
- **Diagnose on desktop on this site.** The general rule is mobile-first; the device split says PC 87.22%. Check a mobile render when a mobile defect is suspected, not as the default lens.
- **Programmatic scroll does not move this site.** `window.scrollTo` and `Element.scrollIntoView` leave `window.scrollY` at 0 — a smooth-scroll library intercepts them. Only real wheel events via the `computer` scroll action move the page, so only they fire a lazy-load. **Scroll with `computer`, never with injected JS, when testing lazy-loaded elements.** Two false "the embed failed to load" readings at run 2 came from this.
