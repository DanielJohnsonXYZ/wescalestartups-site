- **GSC MCP `analytics_query` IS UNUSABLE FOR MEASUREMENT. EVERY DIMENSION NOW ANSWERS ABOUT THE STALE `www.` PROPERTY, WITHOUT ERRORING — INCLUDING `["date"]`.** Runs 21–22 recorded that `["date"]` survived while `["page"]`/`["query"]`/`filters` did not. **Run 23 falsified that: `["date"]` over 2026-08-20→09-02 returned 0 impressions on twelve of thirteen days against a real 163–651/day in the UI.** A run planning around `["date"]` will get zeros and may record them as a traffic collapse. **There is no working API route to this data; the UI is not the preferred route, it is the only one.** Not caused by the phantom accounts — run 22 cleared them first and the bug persisted (two independent faults). - **THE SEARCH CONSOLE UI IS A COMPLETE, RELIABLE PAGE- AND QUERY-LEVEL INSTRUMENT, READ VIA THE DOM (run 22).** This replaces the broken API dimensions entirely. Two things matter: **(1) `get_page_text` IS USELESS HERE — it returns a stale orphaned DOM container and will hand you the 3-month table while the screen shows 28 days.** Run 22 nearly logged 3-month figures as a 28-day window. **(2) Use `javascript_tool`, and select the VISIBLE table — NOT the last one.** Run 22 said "the last one is the live view"; **run 23 falsified that twice in one session** (after switching to Pages, the last of four tables was the stale Days table, and table 0 was the stale 693-row 3-month query set). The reliable selector is `[...document.querySelectorAll('table')].find(t => t.offsetParent !== null && t.getBoundingClientRect().height > 0)`. Map `[...t.rows].map(r=>[...r.cells].map(c=>c.textContent))` and strip the `Copy URL to clipboard|Open in new tab|Inspect URL` cruft from page rows. ## Standing decisions

- **The verification protocol, the lastmod two-step and the noindex two-file rule are in the task file's FIXED RULES. Not restated here.** The two that have cost time: `check:lastmod` cannot fail before the content commit exists (Trap 5), so only the post-push pass means anything; and **pages built − noindexed = sitemap `<loc>` count**, checked after every structural change.
- **Never state unsourced market statistics.** Anchor cost claims on WSS's published ranges; reuse the bands on `/insights/fractional-cmo-cost-uk`.
- **Keep the "point them somewhere better" voice.** Every comparison should name the case where a competitor or a different model is the right buy — brand voice *and* what makes a passage worth citing.
- **When a change is defensible under two competing readings of the data, prefer it** over one needing the ambiguity resolved first.
- **Sweep the connectors before writing anything implying WSS expertise or client work.** The VC guide assumed fund-side experience; there is none. The real position is accelerator-side (Google for Startups, DeepMind, Techstars, GrowthMentor, several hundred founder sessions) — **a mentoring relationship, not client work. Run 20 found a third party had collapsed that distinction off-site and run 21 found the site doing it on `/facts/daniel-johnson`. Do this check every time.**
- **A hub page must not restate its spokes.** Run 3 spent a run undoing a self-competing cluster; do not rebuild one.
- **`src/data/growthTools.ts` is the primary source for what the free tools do** — not any page describing them (runs 13 and 14 both got this wrong). The Scorecard is **12 questions, ~4 min**, scoring **founder dependency** — not the five-layer framework on `/diagnose`. Never describe either in terms of the other.
- **Push large files through a subagent that reads and pushes them itself**, running `git hash-object` on the sandbox file and checking the returned blob SHA matches. The bytes never enter the parent's context and corruption becomes detectable rather than silent. Runs 19 and 21 did every file this way. This is the practical answer to Trap 4.
